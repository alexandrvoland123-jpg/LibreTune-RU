# Подключение к ЭБУ

LibreTune обменивается данными с ЭБУ через последовательное USB-подключение.

## Перед подключением

Убедитесь, что:
1. На ЭБУ подано питание.
2. USB-кабель соединяет ЭБУ с компьютером.
3. Установлены необходимые USB-драйверы (см. раздел [Установка](./installation.md)).

## Открытие окна подключения

1. Нажмите кнопку **Подключить** на панели инструментов;
2. либо выберите **ЭБУ → Подключить**;
3. либо нажмите `Ctrl+Shift+C`.

## Выбор порта

В окне подключения отображаются доступные последовательные порты:
- **Windows:** `COM3`, `COM4` и т. д.
- **macOS:** `/dev/cu.usbserial-*`, `/dev/cu.usbmodem*`.
- **Linux:** `/dev/ttyUSB0`, `/dev/ttyACM0`.

Если порт ЭБУ не отображается:
1. Проверьте USB-кабель.
2. Убедитесь, что на ЭБУ подано питание.
3. Проверьте установку USB-драйверов.
4. Нажмите **Обновить**, чтобы повторно просканировать порты.

## Параметры подключения

| Параметр | Описание | По умолчанию |
|---|---|---|
| **Порт** | Последовательный порт ЭБУ | Автоопределение |
| **Скорость передачи (Baud Rate)** | Скорость обмена данными | 115200 |
| **Тайм-аут** | Время ожидания подключения, мс | 5000 |

### Режим пакетов текущих данных (автоматический выбор)

Если для параметра **Режим пакетов текущих данных** выбрано значение **Auto**, LibreTune выбирает подходящий режим чтения с учётом типа ЭБУ и загруженного INI:

- **Speeduino / MegaSquirt (MS2 / MS3):** Auto всегда выбирает **Force Burst** (команда `A`). Burst — высокоскоростной и проверенный режим получения текущих данных для этих ЭБУ. На некоторых версиях прошивки переключение на OCH приводило к резкому снижению пропускной способности и остановке обновления приборов, поэтому Auto больше не выбирает этот режим для указанных ЭБУ.
- **rusEFI / FOME / epicEFI:** Auto может выбрать **Force OCH**, если загруженный INI описывает чтение блока OCH (`ochGetCommand` / `ochBlockSize`), либо если соединение медленное (Bluetooth / низкая скорость передачи) или измеренное время ответа велико.

Автоматический выбор можно в любой момент переопределить в окне настроек, выбрав режим (**Auto / Force Burst / Force OCH / Disabled**). Если в режиме Auto приборы перестают обновляться или показывают недопустимые значения, сначала попробуйте **Force Burst**.

### Автосинхронизация и переподключение после команд контроллера

Некоторые команды контроллера (например, применение базовых карт или изменение конфигурации ЭБУ) изменяют настройки непосредственно в ЭБУ. LibreTune может не увидеть эти изменения, пока не выполнит новую синхронизацию и, в отдельных случаях, не переподключит последовательный порт.

В окне настроек можно включить параметр **Автосинхронизация и переподключение после команд контроллера**. После выполнения такой команды LibreTune автоматически синхронизирует данные и при необходимости переподключится, чтобы новые настройки ЭБУ отобразились в программе.

> ⚠️ При включении этой опции последовательный порт может временно закрываться и открываться повторно. Используйте её, если планируете выполнять команды, изменяющие конфигурацию ЭБУ, и хотите автоматически получать обновлённые настройки.

## Распространённые скорости передачи

| ЭБУ | Скорость передачи |
|---|---|
| Speeduino | 115200 |
| rusEFI | 115200 |
| epicEFI | 115200 |
| MegaSquirt MS2 | 115200 |
| MegaSquirt MS3 | 115200 |

## Установка соединения

1. Выберите правильный порт.
2. Убедитесь, что скорость передачи соответствует настройкам ЭБУ.
3. Нажмите **Подключить**.

LibreTune выполнит следующие действия:
1. Откроет последовательное соединение.
2. Запросит сигнатуру ЭБУ.
3. Проверит её соответствие загруженному определению INI.
4. Синхронизирует данные калибровки.

## Состояние подключения

В строке состояния отображается состояние соединения:

| Статус | Значение |
|---|---|
| 🔴 Не подключено | Активного соединения нет |
| 🟡 Подключение | Устанавливается соединение |
| 🟢 Подключено | Соединение успешно установлено |
| ⚠️ Частичная синхронизация | Соединение установлено, но некоторые страницы не удалось синхронизировать |

## Несовпадение сигнатуры

Если сигнатура ЭБУ не совпадает с сигнатурой в INI:

1. Появится диалог со следующими вариантами:
   - **Локальные совпадения** — INI-файлы из локального репозитория, сигнатура которых совпадает с сигнатурой ЭБУ.
   - **Совпадения в Интернете** — автоматический поиск в репозиториях GitHub Speeduino / rusEFI / FOME сразу после обнаружения несовпадения. Эти результаты показываются первыми, если локальных совпадений нет.
   - **Продолжить в любом случае** — только для опытных пользователей.
2. Выберите подходящий INI, чтобы обновить проект.

Ничего не загружается и не применяется, пока вы явно не нажмёте **Загрузить**. Автоматически выполняется только поиск.

## Устранение неполадок

### «Порт не найден»
- Проверьте USB-кабель.
- Убедитесь, что ЭБУ включён.
- Установите или переустановите USB-драйверы.
- Попробуйте другой USB-порт.

### «Истекло время ожидания подключения»
- Проверьте скорость передачи.
- Убедитесь, что ЭБУ отвечает (индикаторы мигают).
- Попробуйте выключить и снова включить питание ЭБУ.

### Подробные журналы обмена с ЭБУ

Чтобы увидеть, какие данные отправляются через последовательный порт и принимаются от ЭБУ, запустите LibreTune с включённой отладкой протокола:

```bash
RUST_LOG=libretune_core::protocol=debug cargo tauri dev
```

Установите `RUST_LOG=error`, чтобы скрыть большую часть сообщений серверной части.

### «Сигнатура не совпадает»
- INI-файл не соответствует прошивке ЭБУ.
- Загрузите INI для установленной версии прошивки.
- Либо обновите прошивку ЭБУ до версии, соответствующей INI.

### «Отказано в доступе» (Linux)
- Добавьте пользователя в группу `dialout`:
  ```bash
  sudo usermod -a -G dialout $USER
  ```
- Выйдите из системы и войдите снова.
