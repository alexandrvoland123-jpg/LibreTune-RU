# Сценарии действий

В LibreTune предусмотрена система **сценариев действий (Action Scripting)**, позволяющая записывать, сохранять и повторно выполнять действия по настройке. В этом документе описаны типы действий, API сценариев и распространённые рабочие процессы.

## Обзор

Система сценариев действий позволяет:
- **Записывать действия:** сохранять изменения таблиц, корректировки констант и команды ЭБУ.
- **Воспроизводить сценарии:** повторно выполнять сохранённые действия для другой калибровки или другого ЭБУ.
- **Обмениваться рабочими процессами:** экспортировать и импортировать сценарии действий для совместной работы.
- **Автоматизировать настройку:** создавать последовательности действий, которые можно применять одинаковым образом.

Это полезно для:
- единообразного применения базовых конфигураций к нескольким файлам калибровок;
- документирования изменений настройки для проверки и утверждения;
- обмена методиками настройки с другими специалистами;
- автоматизации повторяющихся корректировок.

## Доступность определяется INI-файлом

Работа сценариев действий строго зависит от загруженного описания ЭБУ в формате INI:
- **Таблицы:** действия доступны и выполняются только для таблиц, определённых в `[TableEditor]` или `[CurveEditor]`.
- **Константы:** действия применяются только к константам, определённым в `[Constants]` (и `[ConstantsExtensions]`).
- **Команды ЭБУ:** действия с необработанными командами доступны только в том случае, если INI содержит раздел `[ControllerCommands]`.

Если в калибровке отсутствует нужный раздел или объект, связанные действия скрываются или пропускаются. Программа не пытается угадывать или создавать их самостоятельно.

## Типы действий

Механизм Action Engine поддерживает следующие атомарные операции. Перед выполнением каждое действие проверяется по текущему загруженному описанию INI.

### Операции с таблицами

| Действие | Описание | Параметры |
|---|---|---|
| `TableEdit` | Изменение одной ячейки | `table_name: string`, `x_index: usize`, `y_index: usize`, `new_value: f64`, `old_value: Option<f64>` |
| `BulkOperation` | Применение операции к нескольким ячейкам | `operation: string` (`set`, `scale`, `smooth`, `offset`, `interpolate`, `rebin`), `table_name: string`, `cells: Vec<(usize, usize)>`, `parameters: Map<String, f64>` |

### Изменение констант

| Действие | Описание | Параметры |
|---|---|---|
| `ConstantChange` | Изменение скалярной константы | `constant_name: string`, `new_value: f64`, `old_value: Option<f64>` |

### Команды ЭБУ

| Действие | Описание | Параметры |
|---|---|---|
| `SendCommand` | Выполнение команды контроллера, определённой в INI | `command: string` |
| `Pause` | Ожидание заданного времени | `duration_ms: u32` |
| `ExecuteLuaScript` | Выполнение пользовательского фрагмента сценария Lua | `script: string` |

## Проверка корректности

Перед выполнением набора действий функция `validate_action_set` проверяет:
1. **Наличие таблицы:** `table_name` существует в `[TableEditor]`.
2. **Наличие константы:** `constant_name` существует в `[Constants]`.
3. **Допустимость команды:** команда `SendCommand` определена в разделе `[ControllerCommands]` файла INI.
4. **Безопасность значений:** значения не являются NaN или бесконечностью.

Если любая проверка завершается ошибкой, выполнение прерывается, чтобы не допустить неопределённого состояния ЭБУ.

## Запись действий

### Через контекстное меню (автоматически)

Все изменения таблиц через панель инструментов записываются автоматически:
1. Нажмите **Set Equal**, **Scale**, **Smooth** и т. п.
2. Действие будет записано с исходными и целевыми ячейками.
3. Продолжайте редактирование обычным способом.
4. Действия накапливаются на панели **Action History** (История действий).

### Добавление события вручную

Чтобы добавить пользовательское действие:
1. Откройте **Tools** → **Action Manager** (Инструменты → Менеджер действий).
2. Нажмите **Insert Action** (Добавить действие).
3. Выберите тип действия в раскрывающемся списке.
4. Заполните параметры.
5. Нажмите **Add** (Добавить).

## Менеджер действий

На панели Action Manager (View → Action Manager) отображаются:

### Список действий

- **#:** номер действия.
- **Type:** тип действия — `SetTableCell`, `ScaleRange`, `SetConstant` и т. п.
- **Target:** имя таблицы или константы.
- **Details:** параметры (ячейки, значение, коэффициент и т. п.).
- **Timestamp:** время записи действия.

### Элементы управления

- **Stop Recording:** приостановить запись новых действий.
- **Clear All:** удалить все записанные действия (с подтверждением).
- **Export:** сохранить действия в файл `.actions.json`.
- **Import:** загрузить действия из файла.
- **Replay:** выполнить все действия по порядку.

### Фильтрация

- **Search:** фильтр действий по типу или целевому объекту (например, `veTable` покажет все действия с таблицами VE).
- **Type Filter:** отображение только выбранных типов действий (таблицы, константы, ЭБУ и т. д.).

## Повторное выполнение действий

### Последовательное выполнение

```
[Пользователь нажимает "Replay All"]
  ├─ Действие 1: SetTableCell(veTable1, 20, 10, 45.5)
  ├─ Действие 2: SetTable Range(veTable1, 15-25, 8-12, 48.0)
  ├─ Действие 3: SetConstant(target_afr, 14.5)
  ├─ Действие 4: Delay(500ms)
  ├─ Действие 5: ScaleTableRange(ignTable, 0-32, 0-16, 1.05)
  └─ Все действия завершены
```

### Условное выполнение

Для действий можно задавать условия:

```json
{
  "type": "SetTableRange",
  "table": "boostTable",
  "condition": "constant('hasBoost') == 1",
  "x_range": [0, 32],
  "y_range": [0, 16],
  "value": 5.0
}
```

Если условие ложно, действие пропускается.

В условиях можно ссылаться только на константы или каналы, существующие в загруженном INI. Если указанный объект отсутствует, условие считается ложным.

## Типичные рабочие процессы

### Применение базовой конфигурации

1. Запишите действия (или импортируйте их из шаблона):
   ```
   SetTableRange(veTable, 0-32, 0-16, 50%)
   SetTableRange(ignTable, 0-32, 0-16, 5°)
   SetConstant(target_afr, 14.5)
   SetConstant(rev_limit, 7000)
   ```
2. Сохраните их в `baseline.actions.json`.
3. Для новой калибровки:
   - откройте менеджер действий;
   - импортируйте `baseline.actions.json`;
   - нажмите **Replay** (Воспроизвести);
   - базовая конфигурация будет применена.

### Поэтапная настройка

Запишите сеанс настройки:
1. Изменяйте ячейки таблицы VE.
2. Корректируйте зажигание.
3. Настраивайте константы.
4. Все действия будут записываться автоматически.

Экспортируйте запись, чтобы задокументировать процесс:
- поделиться ею с другими настройщиками;
- вернуться к использованной методике;
- хранить свой подход в системе контроля версий.

### Совместная работа

1. Настройщик A создаёт `na-baseline.actions.json` с проверенной конфигурацией.
2. Настройщик B импортирует файл в новый проект.
3. Запускает воспроизведение, быстро получая базовую конфигурацию.
4. Продолжает ручную настройку на её основе.

## Ограничения

- **Нет вложенных условий:** условия не могут ссылаться на другие условия.
- **Нет циклов:** действия выполняются последовательно, циклы `for` не поддерживаются.
- **Нет ветвления:** логика `if-else` недоступна; поддерживаются только условные действия.
- **Только синхронизация с локальным кэшем:** действия синхронизируются с локальным кэшем калибровки, а не с данными ЭБУ в реальном времени.
- **Нет отмены после воспроизведения:** выполненные действия нельзя отменить автоматически; при необходимости используйте отмену вручную.

## Устранение неполадок

### Действия не записываются

**Причина:** запись приостановлена.

**Решение:** нажмите **Resume** (Продолжить) в менеджере действий.

### При воспроизведении появляется ошибка «Table not found»

**Причина:** имя целевой таблицы отличается в новой версии INI.

**Решение:**
1. Проверьте имена таблиц в новом INI.
2. Измените `.actions.json`, указав правильные имена.
3. Повторно импортируйте сценарий и запустите воспроизведение.

### Условное действие пропущено

**Причина:** выражение условия вернуло `false`.

**Решение:**
1. Проверьте значения констант.
2. Проверьте синтаксис условия.
3. Удалите условие, если действие должно выполняться всегда.
