# Руководство по переходу плагинов с Java на WASM

**Статус:** система плагинов Java/JVM объявлена устаревшей 4 февраля 2026 года.  
**Целевая платформа:** система плагинов LibreTune WASM (нативная, изолированная, не требующая JRE).

## 1. Обзор

Система плагинов LibreTune на Java обеспечивала совместимость с JAR-плагинами TunerStudio за счёт запуска отдельного процесса JVM и анализа Swing-интерфейса. Нативная система WASM заменяет этот механизм безопасной средой выполнения внутри процесса с явными разрешениями. Она быстрее загружается и проще распространяется.

Это руководство описывает перенос плагинов Java/Swing на WASM.

## 2. Основные различия

| Область | Плагины Java (устарели) | Плагины WASM (текущая система) |
|---|---|---|
| Среда выполнения | Внешняя JVM (JRE 11+) | Встроенная (wasmtime) |
| Интерфейс | Swing (анализируется приложением) | Нативный интерфейс LibreTune или режим без интерфейса |
| Безопасность | Полный набор разрешений JVM | Явно заданные разрешения |
| Упаковка | JAR + manifest | .wasm + manifest |
| Обмен данными | JSON-RPC через stdin/stdout | Вызовы функций хоста |

## 3. Контрольный список миграции

1. **Инвентаризация:** перечислите все обращения к данным, элементы интерфейса и callback-функции Java-плагина.
2. **Выбор языка:** для WASM-плагинов рекомендуется Rust — для него доступны наиболее подходящие инструменты.
3. **Определение разрешений:** точно установите, что требуется плагину: `ReadTables`, `WriteConstants`, `SubscribeChannels`, `ExecuteActions`.
4. **Перенос логики:** перенесите обработку данных и логику работы с ЭБУ в функции WASM.
5. **Замена интерфейса:** замените Swing-интерфейс нативным интерфейсом LibreTune либо используйте плагин без собственного интерфейса.
6. **Тестирование:** загрузите плагин через менеджер плагинов LibreTune и проверьте результаты.

## 4. Соответствие разрешений

| Возможность Java API | Разрешение WASM |
|---|---|
| Чтение данных таблиц | `ReadTables` |
| Запись константы | `WriteConstants` |
| Подписка на каналы | `SubscribeChannels` |
| Выполнение действий | `ExecuteActions` |

## 5. Соответствие API

### Java (устаревшая система)

Типичные вызовы Java API плагинов:
- `getParameters()` → список констант.
- `setParameter()` → изменение значений констант.
- `getRealtimeData()` → доступ к каналам.
- `getUI()` → Swing-интерфейс.

### WASM (текущая система)

Основные функции хоста WASM:
- `get_table_data(table_name)`
- `get_constant(constant_name)`
- `set_constant(constant_name, value)`
- `subscribe_channel(channel_name)`
- `get_channel_value(channel_name)`
- `execute_action(action_json)`
- `log_message(message)`

## 6. Стратегия переноса интерфейса

В Java-плагинах использовались компоненты Swing, например `JPanel`, `JTextField` и `JButton`. Для WASM-плагинов следует выбрать один из вариантов:

**Вариант A — плагины без собственного интерфейса (рекомендуется)**
- Реализуйте только вычислительную логику.
- Не создавайте собственный интерфейс.
- Используйте существующие элементы интерфейса LibreTune для отображения результатов.

**Вариант B — интеграция с нативным интерфейсом**
- Добавьте в интерфейс LibreTune новую панель или диалог (React/TypeScript).
- Свяжите его с плагином через события или общие данные.
- Этот вариант лучше подходит для сложных сценариев взаимодействия.

## 7. Пример плана миграции

**Поведение Java-плагина:**
- чтение таблицы VE;
- применение алгоритма сглаживания;
- запись изменённой таблицы;
- простой интерфейс для задания коэффициента сглаживания.

**Перенос на WASM:**
1. Вызовите `get_table_data("veTable1Tbl")`.
2. Выполните сглаживание в WASM.
3. Используйте `set_constant()` или будущую функцию `set_table_data()` (если она будет предоставлена).
4. Для задания коэффициента сглаживания используйте диалог LibreTune, затем запустите выполнение плагина.

## 8. Упаковка

### Java (устаревшая система)
- JAR-файл.
- Manifest с `TunerStudio-Plugin` или `Main-Class`.

### WASM (текущая система)
- бинарный файл `.wasm`;
- manifest `plugin.toml` (имя, версия, разрешения).

## 9. Тестирование

Используйте менеджер плагинов LibreTune:
1. Загрузите файл `.wasm`.
2. Проверьте запросы разрешений.
3. Запустите `execute()` или точку входа плагина.
4. Проверьте результаты или изменения в ЭБУ.

## 10. Типичные ошибки

- **Интерфейс необходимо переписать:** Swing-интерфейсы не переносятся автоматически.
- **Разрешения должны быть указаны явно:** отсутствие нужного разрешения блокирует вызовы функций хоста.
- **WASM работает в изолированной среде:** доступ к файловой системе запрещён, если он не предусмотрен явно.
