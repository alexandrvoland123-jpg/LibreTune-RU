# Руководство по статистике данных

Панель статистики в регистраторе данных (Data Logger) предоставляет подробный статистический анализ записанных параметров двигателя. Она помогает оценить стабильность данных, обнаружить аномалии и проверить результат изменений калибровки.

## Обзор

При анализе записанных данных статистика помогает ответить на важные вопросы:
- Насколько стабилен AFR? (это показывает стандартное отклонение).
- Каково типичное значение? (разница между средним и медианой помогает обнаружить выбросы).
- Улучшили ли внесённые изменения калибровки результат? (сравнение до и после).
- Есть ли проблемы с датчиками? (скачки минимума или максимума могут указывать на сбои).

## Открытие панели статистики

### В окне Data Logger

1. **Запишите или загрузите журнал** в Data Logger.
2. Переключитесь в режим **Playback** (переключатель в верхней части окна).
3. Нажмите кнопку **Stats**, чтобы открыть панель статистики.
4. Выберите канал для анализа или откройте **таблицу сравнения нескольких каналов**.

### Быстрый просмотр статистики

Панель статистики отображает:
- **Подробный просмотр одного канала:** таблица из 8 строк со всеми статистическими показателями.
- **Таблица нескольких каналов:** компактное сравнение всех каналов рядом.

## Объяснение статистических показателей

### Среднее значение (Mean / Average)

**Формула:** сумма всех значений ÷ количество выборок.

**Что показывает:**
- типичное значение канала;
- удобно для сравнения исходных данных между заездами;
- чувствительно к крайним выбросам.

**Пример:** среднее AFR = 14.2.
- В среднем система регулирования lambda поддерживает значение 14.2.
- Сравните его с целевым AFR, чтобы понять, нужны ли корректировки.

**Когда полезно:** при проверке, находится ли калибровка около требуемого значения.

---

### Медиана (50-й процентиль)

**Что показывает:**
- центральное значение после сортировки всех выборок;
- не зависит от крайних выбросов;
- часто лучше среднего отражает «типичное» значение.

**Пример:** медиана AFR = 14.1, среднее AFR = 14.2.
- Медиана и среднее близки — распределение данных симметрично.
- Выбросов мало.

**Когда полезно:** при определении истинного центра распределения данных.

---

### Стандартное отклонение (Std Dev)

**Формула:** квадратный корень из среднего квадрата отклонений от среднего значения.

**Что показывает:**
- меру разброса или «шума» в данных;
- меньшее стандартное отклонение означает более стабильные и согласованные данные;
- большее стандартное отклонение означает больше шума и меньшую стабильность.

**Пример:** стандартное отклонение AFR = 0.3 или 1.2.
- 0.3 — очень стабильное регулирование AFR.
- 1.2 — заметные колебания AFR или шум датчика.

**Интерпретация:**
- **< 0.2:** отличное регулирование (узкий диапазон).
- **0.2–0.5:** хорошее регулирование (типично для настроенного двигателя).
- **0.5–1.0:** приемлемо, но есть возможности для улучшения.
- **> 1.0:** плохое регулирование или зашумлённый датчик.

**Когда полезно:** при проверке результатов AutoTune (стандартное отклонение должно уменьшаться).

---

### Минимум / максимум (Min / Max)

**Что показывают:**
- наименьшее и наибольшее записанные значения;
- диапазон = Max − Min;
- помогают обнаружить крайние отклонения.

**Пример:** AFR min = 12.5, max = 15.8, диапазон = 3.3.
- AFR меняется от достаточно богатой до достаточно бедной смеси.
- Большой диапазон может указывать на проблемы регулирования или переходные режимы.

**Когда полезно:**
- для поиска скачков показаний датчика (нереалистичных крайних значений);
- для определения наиболее сильных отклонений;
- для проверки безопасных рабочих границ.

---

### Процентили (P25, P75)

**Что показывают:**
- P25: ниже этого значения находятся 25% выборок (первый квартиль).
- P75: ниже этого значения находятся 75% выборок (третий квартиль).
- Вместе они описывают центральные 50% данных — диапазон между P25 и P75.

**Пример:** AFR P25 = 13.9, P75 = 14.3.
- 50% показаний AFR находятся между 13.9 и 14.3.
- Это показывает основной рабочий диапазон.

**Когда полезно:** для анализа распределения данных без искажения из-за выбросов.

---

### Межквартильный размах (IQR)

**Формула:** P75 − P25.

**Что показывает:**
- разброс центральных 50% данных;
- меньший IQR означает более плотную концентрацию около центра;
- больший IQR означает более широкий разброс.

**Пример:** IQR = 0.4 (P75=14.3, P25=13.9).
- Центральные 50% данных охватывают диапазон всего 0.4 единицы AFR.
- Данные стабильны и сгруппированы в узком диапазоне.

**Когда полезно:** для быстрой оценки стабильности регулирования.

---

## Сценарии анализа

### Поиск нестабильных каналов

**Цель:** определить, какие датчики или системы управления дают зашумлённые показания.

**Обратите внимание на:**
1. Большое стандартное отклонение (> 1.0).
2. Большую разницу между средним и медианой.
3. Большой IQR относительно самого значения.
4. Крайние значения минимума/максимума.

**Пример:**
```
Channel: IAT (Intake Air Temperature)
Mean: 82°F
Std Dev: 2.5°F  ← Слишком много для установившегося режима!
Min: 58°F
Max: 95°F
```

**Проверка:**
- Датчик IAT работает, но показания сильно зашумлены.
- Возможные причины: неплотный разъём, смешивание потоков воздуха во впуске, неисправность датчика.
- Решение: проверьте проводку датчика и при необходимости замените его.

---

### Сравнение версий калибровки (до/после)

**Цель:** проверить, действительно ли изменения калибровки улучшили работу.

**Шаг 1. Запишите исходные данные.**
1. Загрузите исходную калибровку в ЭБУ.
2. Выполните одинаковую тестовую поездку (тот же маршрут и условия).
3. Запишите данные с помощью автоматической записи.
4. Сохраните журнал как `baseline_tune_log.csv`.

**Шаг 2. Примените изменения и повторите запись.**
1. Загрузите изменённую калибровку в ЭБУ.
2. Повторите ту же тестовую поездку.
3. Запишите данные с помощью автоматической записи.
4. Сохраните журнал как `modified_tune_log.csv`.

**Шаг 3. Сравните статистику.**

Откройте оба журнала в режиме Playback программы Data Logger:

| Канал | Исходная версия | Изменённая версия | Улучшение |
|---|---:|---:|---|
| AFR Mean | 14.5 | 14.2 | Целевое значение достигнуто (14.2) ✓ |
| AFR Std Dev | 0.8 | 0.3 | **Более стабильное значение!** ✓ |
| AFR IQR | 1.2 | 0.5 | Лучшее регулирование ✓ |
| MAP Std Dev | 2.1 | 1.8 | Небольшое улучшение ✓ |
| Timing Std Dev | 3.5 | 2.1 | **Заметное улучшение!** ✓ |

**Интерпретация:** все показатели улучшились — изменения калибровки дали положительный результат.

---

### Поиск выбросов

**Цель:** обнаружить некорректные точки данных или переходные процессы.

**Способ 1. Сравните среднее и медиану.**
```
Channel: Lambda
Mean: 1.003
Median: 0.998
Difference: 0.005  ← Существенная разница!
```

**Интерпретация:** среднее смещено вверх несколькими высокими значениями.
- Присутствуют выбросы, вероятно, во время ускорения.
- Медиана (0.998) лучше отражает центральное значение.

**Способ 2. Проверьте P25 и P75.**
```
Channel: CLT (Coolant Temperature)
Min: 155°F
P25: 182°F  ← 25% данных
Median: 185°F
P75: 187°F  ← 75% данных
Max: 210°F  ← Скачок!
```

**Интерпретация:**
- Типичная температура охлаждающей жидкости находится в узком диапазоне 182–187°F.
- Скачок до 210°F является выбросом.
- Это может быть переходный процесс после запуска или сбой датчика.

## Примеры из практики

### Пример 1. Хорошо настроенный двигатель

```
AFR Statistics (stock fuel map):
Mean: 14.0
Median: 14.1
Std Dev: 0.25
Min: 13.2
Max: 14.8
P25: 13.9
P75: 14.2
IQR: 0.3
```

**Что это показывает:**
- ✓ AFR находится около целевого значения (14.0).
- ✓ Показания очень стабильны (Std Dev = 0.25).
- ✓ Разброс небольшой (IQR = 0.3).
- ✓ Минимум и максимум находятся в разумных пределах (разница 0.8).

**Вывод:** отличное регулирование состава смеси с обратной связью.

---

### Пример 2. Проблема управления наддувом

```
MAP (Manifold Air Pressure):
Mean: 12.5 psi
Std Dev: 2.8 psi  ← Высокое значение!
Min: 8.2
Max: 18.5  ← Большой скачок!
P25: 11.2
P75: 13.8
IQR: 2.6
```

**Что это показывает:**
- ✗ Управление наддувом нестабильно (Std Dev = 2.8).
- ✗ Большие колебания (IQR = 2.6).
- ✗ Скачок до 18.5 может указывать на превышение целевого наддува.

**Диагностика:**
- Пружина вестгейта может быть слишком слабой.
- Требуется настройка PID-регулятора целевого наддува.
- Проверьте утечки наддува.

**Действие:** скорректируйте параметры управления наддувом и повторите тест.

---

### Пример 3. Проблема датчика AFR

```
AFR (from sensor):
Mean: 14.1
Median: 13.95  ← Отличается от среднего!
Std Dev: 0.6
Min: 11.2  ← Очень бедно
Max: 17.8  ← Очень богато
P25: 13.7
P75: 14.5
IQR: 0.8
```

**Что это показывает:**
- ✗ Среднее и медиана различаются — присутствуют выбросы.
- ✗ Высокое стандартное отклонение (0.6).
- ✗ Нереалистичные минимум (11.2) и максимум (17.8).
- Возможна неисправность датчика или периодический обрыв проводки.

**Диагноз:** показания AFR нестабильны и содержат резкие скачки.

**Действия:**
- проверьте разъём и проводку датчика;
- проверьте датчик на стенде;
- замените его при неисправности.

## Советы по интерпретации данных

### «Стандартное отклонение слишком велико» — что делать?

1. **Проверьте переходные процессы.**
   - Пики и провалы при разгоне и торможении ожидаемы.
   - Для проверки исправности датчика записывайте установившийся режим.
2. **Сравните несколько датчиков.**
   - Если AFR зашумлён, а CLT стабилен, проблема может быть связана с конкретным датчиком.
   - Если зашумлены несколько каналов, возможны электромагнитные помехи или проблемы с проводкой.
3. **Сравните с исходными данными.**
   - Если исходная запись тоже была зашумлена, это не ухудшение.
   - Если исходная запись была чистой, значит, что-то изменилось.

### «Среднее и медиана сильно различаются» — что делать?

1. **Изучите выбросы.**
   - В какой части журнала они появляются (запуск, полный газ WOT)?
   - Ожидаемы ли они в этих условиях движения?
2. **Разделите журнал на участки.**
   - Отдельно запишите движение с постоянной скоростью.
   - Отдельно запишите разгон.
   - Для каждого участка статистика должна иметь меньший разброс.
3. **Определите, допустимы ли выбросы.**
   - Переходные процессы холодного запуска нормальны.
   - Отсечка топлива при торможении двигателем нормальна.
   - Скачки датчика не являются нормой.

### «Статистика выглядит хорошо, но автомобиль работает не так, как настроенный» — почему?

Возможные причины:
- **Важен временной интервал:** один пятиминутный журнал может быть нерепрезентативным.
  - Записывайте данные в разное время суток и при разной температуре.
  - Записывайте именно те режимы движения, которые важны для вас.
- **Выбор каналов:** возможно, записываются не те каналы.
  - Убедитесь, что анализируете правильный вход датчика.
  - Проверьте масштабирование и единицы измерения.
- **Манера вождения:** при одной и той же калибровке результаты могут отличаться.
  - Одинаковые движения дросселем дают сопоставимые журналы.
  - Резкое нажатие на газ вызывает более сильные колебания.

## Совместная работа с другими функциями

### С интеллектуальной записью

1. Включите автоматическую запись в Data Logger.
2. Проедьте обычный маршрут без ручного запуска и остановки записи.
3. Выполните несколько проездов по одному маршруту.
4. Сравните статистику разных проездов:
   - одинаковая статистика означает воспроизводимую работу калибровки;
   - различия могут быть связаны с условиями движения (температура, трафик и т. д.).

### С AutoTune

1. Запишите исходный заезд с оригинальной калибровкой.
2. Изучите исходную статистику (Std Dev, среднее, диапазон).
3. Выполните сеанс AutoTune и примените рекомендации.
4. Повторите ту же поездку с изменённой калибровкой.
5. Сравните статистику:
   - стандартное отклонение AFR должно уменьшиться;
   - среднее AFR должно соответствовать целевому значению;
   - общая стабильность должна улучшиться.

### С калькулятором производительности

1. Рассчитайте ожидаемые мощность и крутящий момент по параметрам калибровки.
2. Запишите заезд на диностенде или разгон.
3. Изучите статистику для соответствующей нагрузки.
4. Убедитесь, что калибровка соответствует заданным параметрам:
   - AFR должен соответствовать целевому стехиометрическому значению;
   - угол зажигания должен соответствовать таблице;
   - наддув должен соответствовать цели (если установлен турбонаддув).
