# Алгоритм AutoTune

AutoTune — адаптивная система корректировки топливных таблиц LibreTune. Она анализирует реальные данные движения (RPM, MAP, AFR) и формирует рекомендации, позволяющие приблизить фактический AFR к целевому за счёт изменения значений таблицы VE.

## Обзор

Алгоритм AutoTune решает три основные задачи настройки ЭБУ:

1. **Задержка Lambda** — датчики AFR сообщают результат сгорания через 50–500 мс после впрыска топлива.
2. **Фильтрация переходных процессов** — изменение положения дросселя вызывает обогащение, которое не следует компенсировать изменением VE.
3. **Качество данных** — не все точки данных одинаково полезны для настройки.

## Основной алгоритм

### 1. Сбор точек данных

Каждая выборка данных реального времени преобразуется в `VEDataPoint`:

```rust
pub struct VEDataPoint {
    pub rpm: f64,              // Engine speed (RPM)
    pub map: f64,              // Manifold pressure (kPa)
    pub afr: f64,              // Measured air-fuel ratio
    pub target_afr: f64,       // Target AFR from tune
    pub tps: f64,              // Throttle position (0-100%)
    pub tps_rate: f64,         // TPS change rate (%/sec)
    pub accel_enrich_active: Option<bool>,  // ECU acceleration enrichment flag
    pub fuel_cut_active: Option<bool>,      // Overrun fuel-cut flag (DFCOOn/dfco channels)
    pub timestamp_ms: u64,     // Timestamp for correlation
}
```

**Частота сбора данных:** соответствует потоку данных реального времени (номинально 10 Гц; на реальном оборудовании часто встречается интервал 111–200 мс, когда одиночные чтения конкурируют с опросом реального времени за блокировку соединения).

### 2. Компенсация задержки Lambda

Показание датчика AFR в момент времени T соответствует топливу, впрыснутому в момент T−Δ, где Δ — задержка lambda.

**Порядок выбора задержки** (используется первое подходящее значение):

1. **Фиксированная измеренная задержка** — `lambda_delay_ms > 0` в настройках. Сюда следует вводить результат [теста задержки AFR](../features/tools.md): на реальном автомобиле задержка выхлопной системы часто составляет 400–1000 мс, что значительно больше значений RPM-кривой.
2. **Таблица задержки по ячейкам** — `reference_tables.lambda_delay_table` (массив `[row][col]`, соответствующий расположению таблицы VE), если она задана.
3. **Резервная кривая по RPM** (используется по умолчанию, если ничего не настроено):

```
delay_ms = 200 - (150 * (rpm - 800) / (6000 - 800))
```

| RPM | Задержка |
|---:|---:|
| 800 (холостой ход) | 200 мс |
| 3400 (крейсерский режим) | 125 мс |
| 6000 (красная зона) | 50 мс |

**Реализация:**
```rust
fn get_lambda_delay_ms(rpm: f64) -> u64 {
    let rpm_clamped = rpm.clamp(800.0, 6000.0);
    let delay = 200.0 - (150.0 * (rpm_clamped - 800.0) / (6000.0 - 800.0));
    delay as u64
}
```

**Вариант масштабирования задержки по потоку:** если установлен `lambda_delay_flow_scaled`, значение `lambda_delay_ms` задаёт задержку при низком потоке (холостой ход/крейсерский режим) для формируемой таблицы задержек по ячейкам. По мере увеличения потока выхлопных газов — приблизительно оцениваемого как rpm·load·VE — задержка уменьшается в сторону `lambda_delay_floor_ms` (асимптота при высоком потоке, по умолчанию 120 мс). Транспортная задержка приблизительно равна объёму выпускного тракта, делённому на поток, поэтому такой подход напрямую моделирует физику процесса вместо использования одного постоянного значения.

**Размер буфера сопоставления** зависит от используемой задержки: буфер хранит данные как минимум за период «настроенная задержка + 500 мс». Он никогда не становится меньше исторического значения 500 мс, поэтому при большой измеренной задержке не возникает нехватки истории.

**Сопоставление точек данных:**
1. Текущее показание AFR помещается в буфер.
2. Находится историческая точка данных с временной меткой `timestamp_now - delay_ms`.
3. Окно сопоставления составляет **0.6 × измеренный средний интервал между выборками потока** (но не меньше исторического значения 50 мс). Если выборки поступают через T мс, ближайшая к целевому моменту выборка отстоит от него не более чем на T/2. Фиксированное окно 50 мс раньше приводило к отбрасыванию от трети до половины выборок на реальном оборудовании.
4. Исторические RPM/MAP определяют, какую ячейку VE следует обновить.
5. Текущее значение AFR используется для расчёта корректировки.

**Выборки, не содержащие информации о составе смеси, сразу отбрасываются** (причина каждого отклонения указывается в диагностическом журнале):
- **Отсечка топлива при торможении двигателем** (`fuel_cut_active == true`): форсунки выключены, широкополосный датчик показывает предельно бедную смесь. Без фильтра каждая такая выборка требовала бы максимального обогащения именно в ячейках малой нагрузки, через которые проходит двигатель при каждом отпускании педали газа.
- **Широкополосный датчик на пределе диапазона** (`afr < 10.0 || afr > 19.5`): работающий двигатель не поддерживает такие показания. Обычно это означает, что датчик находится в состоянии ограничения, нагреватель не запитан или последствия отсечки топлива ещё не исчезли. Это также покрывает отсечку топлива на ЭБУ, которые не предоставляют канал DFCO.

### 3. Фильтрация переходных процессов

Точки данных отбрасываются во время переходных процессов дросселя, чтобы не компенсировать обогащение при ускорении.

**Условия фильтрации** (должны выполняться все):
- `tps_rate < max_tps_rate` (по умолчанию 10%/сек);
- `accel_enrich_active == false` (если ЭБУ предоставляет этот сигнал);
- RPM и MAP находятся в пределах таблицы.

**Расчёт скорости изменения TPS:**
```rust
tps_rate = (tps_current - tps_previous) / time_delta_sec
```

**Почему это важно:** при быстром открытии дросселя ЭБУ добавляет топливо (ускорительное обогащение), компенсируя осаждение топлива на стенках впускного тракта. Это предусмотренный режим, и его нельзя «убирать настройкой» путём снижения значений VE.

### 4. Взвешивание попаданий в ячейки

Не все точки данных равноценны. LibreTune использует взвешенное усреднение на основе следующих факторов.

**Факторы веса:**

1. **Стабильность RPM** — больший вес для стабильных оборотов.
   ```
   w_rpm = 1.0 / (1.0 + abs(rpm_current - rpm_previous))
   ```
2. **Стабильность MAP** — больший вес для стабильного давления во впуске.
   ```
   w_map = 1.0 / (1.0 + abs(map_current - map_previous))
   ```
3. **Ошибка AFR** — больший вес для небольших ошибок (уменьшает колебания).
   ```
   error_ratio = abs(afr - target_afr) / target_afr
   w_error = exp(-error_ratio * 2.0)
   ```
4. **Общий вес:**
   ```
   weight = w_rpm * w_map * w_error
   ```

### 5. Расчёт рекомендаций

Для каждой ячейки таблицы VE (RPM, MAP) выполняется накопление:

```rust
pub struct CellRecommendation {
    pub sum_corrections: f64,  // Σ(weight * correction)
    pub sum_weights: f64,      // Σ(weight)
    pub hit_count: u32,        // Number of data points
}
```

**Коэффициент коррекции AFR:**
```
correction = target_afr / measured_afr
```

- Если AFR = 14.7, а Target = 13.5: correction = 0.918 (требуется больше топлива, VE нужно увеличить).
- Если AFR = 12.8, а Target = 13.5: correction = 1.055 (смесь слишком богатая, VE нужно уменьшить).

**Взвешенная рекомендация:**
```
recommendation = (sum_corrections / sum_weights)
```

**Применение к таблице VE:**
```
new_ve = old_ve * recommendation
```

### 6. Ограничения степени влияния

Рекомендации ограничиваются, чтобы не допустить опасных изменений.

**Абсолютный предел** (по умолчанию ±20%):
```
change = new_ve - old_ve
if abs(change) > max_absolute_change:
    new_ve = old_ve + sign(change) * max_absolute_change
```

**Процентный предел** (по умолчанию ±20%):
```
ratio = new_ve / old_ve
if ratio > (1.0 + max_percent / 100.0):
    new_ve = old_ve * (1.0 + max_percent / 100.0)
elif ratio < (1.0 - max_percent / 100.0):
    new_ve = old_ve * (1.0 - max_percent / 100.0)
```

**Зачем нужны оба ограничения?**
- Абсолютный предел предотвращает большие скачки в областях с низкими значениями VE (холостой ход).
- Процентный предел предотвращает большие относительные изменения при небольших абсолютных корректировках в областях с высокими значениями VE (WOT).

### 7. Блокировка ячеек

Пользователь может заблокировать отдельные ячейки, чтобы AutoTune не изменял их.

**Примеры использования:**
- ячейки с проверенными значениями, полученными при настройке на диностенде;
- крайние области с недостаточным количеством данных;
- ячейки, требующие ручной настройки (например, зоны управления наддувом).

**Реализация:** заблокированные ячейки пропускаются при применении рекомендаций.

### AutoTuneState
```rust
pub struct AutoTuneState {
    pub running: bool,
```

```rust

    pub min_map: f64,              // Minimum MAP (default: 20 kPa)
```

## Характеристики производительности

- **Память:** O(n*m + k), где n×m — размеры таблицы, k — размер буфера.
- **CPU на одну выборку:** O(log k) для добавления в буфер + O(1) для поиска ячейки.
- **Очистка буфера:** O(k) раз в секунду (удаляются данные старше 500 мс).

Типичное использование памяти: около 10 КБ для таблицы 16×16 с буфером из 100 точек.

## Сходимость алгоритма

Обычно AutoTune достигает значений VE с отклонением не более 5% от оптимальных после следующего времени:
- **Малая нагрузка (крейсерский режим):** 5–10 минут движения.
- **Средняя нагрузка (разгон):** 10–20 минут.
- **Полная нагрузка (WOT):** требуется несколько разгонов с полностью открытым дросселем (3–5 заездов).

**Факторы, влияющие на сходимость:**
1. Охват данными (необходимо пройти все области RPM/MAP).
2. Точность датчика AFR (узкополосный или широкополосный).
3. Ограничения степени влияния (меньшие пределы — медленнее, но безопаснее).
4. Стабильность двигателя (пропуски воспламенения создают шум в AFR).

## Ограничения

1. **Точность датчика:** принцип «мусор на входе — мусор на выходе». Неисправный датчик O2 приводит к неправильной настройке.
2. **Предположение об одном типе топлива:** алгоритм предполагает постоянное октановое число и качество топлива.
3. **Ориентация на установившийся режим:** лучше всего работает при стабильных RPM/MAP и менее эффективен в переходных режимах.
4. **Нет обнаружения детонации:** алгоритм не может обнаруживать детонацию (для этого требуется отдельный анализ сигнала датчика детонации).
5. **Настройка только VE:** не изменяет угол зажигания, управление наддувом и другие параметры.

| LibreTune AutoTune | ✅ По RPM | ✅ Скорость TPS + флаг ускорительного обогащения | ✅ По стабильности | ✅ Абсолютные + процентные |
