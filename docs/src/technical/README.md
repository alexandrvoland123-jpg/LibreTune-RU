# Техническая документация

В этом разделе подробно описаны основные алгоритмы, структуры данных и протоколы LibreTune. Материал предназначен для разработчиков, опытных пользователей и всех, кто хочет разобраться во внутреннем устройстве программы.

- **[Алгоритм AutoTune](./autotune-algorithm.md)** — компенсация задержки Lambda, фильтрация переходных режимов и отключения подачи топлива, весовые коэффициенты попаданий и расчёт рекомендаций.
- **[Операции с таблицами](./table-operations.md)** — алгоритмы интерполяции, сглаживания, масштабирования и изменения разбиения сетки.

### Форматы данных

- **[ИИ-ассистент](./ai-assistant.md)** — цикл работы агента с пользовательской LLM, интерфейс провайдера и расширения проверки.

## Принципы разработки

Техническая реализация LibreTune следует нескольким принципам:

1. **Безопасность типов** — широкое использование системы типов Rust для предотвращения ошибок на этапе компиляции.
2. **Обработка ошибок** — все операции возвращают `Result<T, E>`, обеспечивая явную обработку ошибок.
3. **Производительность** — разбор данных без копирования, эффективное использование памяти и асинхронный ввод-вывод.
4. **Совместимость** — поддержка нескольких платформ ЭБУ при сохранении чётких программных абстракций.
5. **Тестируемость** — модульные тесты для всех критически важных алгоритмов и структур данных.

## Организация исходного кода

```
crates/
├── libretune-core/          # Библиотека на чистом Rust (без зависимостей от UI)
│   ├── src/
│   │   ├── autotune/         # Алгоритмы AutoTune (включая delay_measure.rs,
│   │   │                    # тест измерения транспортной задержки AFR)
│   │   ├── ini/              # Парсер INI и структуры данных
│   │   ├── protocol/         # Протоколы связи с ЭБУ
│   │   ├── table_ops.rs      # Алгоритмы обработки таблиц
│   │   ├── table_file.rs     # Ввод-вывод отдельных таблиц TunerStudio .table
│   │   ├── pin_conflict.rs   # Поиск конфликтов выводов и правила блокировки
│   │   ├── dash/             # Парсер и запись формата панелей приборов
│   │   ├── project/          # Проекты и контроль версий
│   │   └── lua/              # Среда выполнения сценариев Lua
│   └── tests/                # Модульные и интеграционные тесты
└── libretune-app/           # Настольное приложение Tauri
    ├── src-tauri/           # Серверная часть Rust (команды Tauri; отдельный
    │   │                    # модуль для каждой темы в src/commands/)
    └── src/                 # Интерфейс React (TypeScript)
```

## Характеристики производительности

| Операция | Сложность | Примечания |
|---|---|---|
| Разбор INI | O(n) | Однопроходный парсер с минимальным количеством выделений памяти |
| Интерполяция таблицы | O(1) | Билинейная интерполяция для двумерных таблиц |
| Рекомендация AutoTune | O(k) | k — количество точек данных в буфере |
| Отрисовка панели приборов | O(g) | g — количество приборов; целевая частота 60 FPS |
| Коммит Git | O(n) | n — количество изменённых страниц |

## Потокобезопасность

Для безопасного выполнения параллельных операций LibreTune использует систему владения Rust и асинхронную среду выполнения tokio:

- **Связь с ЭБУ** — одно подключение на проект, защищённое через `Arc<Mutex<Connection>>`.
- **Потоковая передача данных в реальном времени** — фоновая задача tokio отправляет события в интерфейс.
- **Состояние AutoTune** — состояние защищено Mutex в структуре AppState.
- **Настройки** — атомарная запись файлов с использованием временных файлов и переименования.
